# GitHub Project / Kanban

## Board columns

1. Backlog
2. Ready
3. Sprint
4. In Progress
5. Review
6. Testing
7. Done

## Required issue fields

- Title
- Epic
- Sprint
- Requirement ID
- Story ID
- Priority
- Status
- Acceptance criteria
- Test evidence
- Documentation impact
- Deployment impact

## Work-in-progress limits

- In Progress: maximum 2
- Review: maximum 2
- Testing: maximum 2

## Movement rules

- Backlog → Ready only when Definition of Ready is met.
- Ready → Sprint only during explicit Sprint planning.
- Sprint → In Progress only when capacity exists.
- Testing → Done only with evidence.
- Failed testing returns to In Progress with the defect documented.
